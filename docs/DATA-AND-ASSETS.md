# 天文数据与外观资源

日期：2026-11-24。首版星历、全部 37 张地图及原始署名已准备并用于实际应用。资源清单由版本化脚本与 `assets/sources/textures.json` 管理，大文件不进入 Git。

## 1. 已核对的基础

通过用户提供的 HTTPS 代理读取了 NAIF 官方工具说明、规则、行星／卫星 SPK 目录与摘要、LSK／PCK 目录，以及 NASA CGI Moon Kit 和媒体使用说明。

- [CSPICE Toolkit](https://naif.jpl.nasa.gov/naif/toolkit.html)：官方当前列出的版本为 N0067，发布于 2022-01-03。接口长期稳定；官方 kernel 目录仍有 2026 年更新。选择它是为了复用成熟星历计算与当前数据，不以 Toolkit 版本日期冒充近期算法变更。
- [C 平台列表](https://naif.jpl.nasa.gov/naif/toolkit_C.html)：列出 Mac/M1 clang、Mac/Intel Apple C、Linux 和 Windows 64 位环境，符合首期及后续移植需求。准备脚本按主机选择 `MacM1_OSX_clang_64bit` 或 `PC_Linux_GCC_64bit` 的 N0067 包；两者生成的星历子集与参考样本结果一致。
- [行星摘要](https://naif.jpl.nasa.gov/pub/naif/generic_kernels/spk/planets/aa_summaries.txt)、[卫星摘要](https://naif.jpl.nasa.gov/pub/naif/generic_kernels/spk/satellites/aa_summaries.txt)：提供实际目标身份、中心和时间覆盖。
- [GPU 接入](../../scoop/docs/specs/SCOOP-GRAPHICS-GPU-SPEC.md)：现有 Scoop 具备设备访问、原生纹理写入和 GPU Image 合成，无需为本应用先新增一套 GPU 框架。

本机已检查的 Scoop 安装入口为同级 `scoop-install/bin/scoop`，显示版本 `0.0.0-dev.20261123`，revision `3910a8c5ee14722d0f15f46d3619b6a24bd6add4`；对应安装树存在 `GpuDevice` 源码。该工具链已完成本项目的编译、测试、Metal 实际绘制与 `.app` 打包。Linux 使用 `~/.scoop` 安装的 `0.0.0-dev.20261124`，revision `f1bc9aa040bd7e69314592ca334313aa2c0f4298`，完成编译、测试、GLES 实际绘制与 deb 打包。

## 3. 星历方案

### 3.2 准备与发布

官方卫星原始文件有数百 MB 至数 GB 的单文件，不直接把整套原始数据复制进应用。准备脚本使用 NAIF 提供的 SPK 工具，按目标与时间段提取所需 segment，保留满足参考中心链的记录，生成有项目名称的新资源文件。原文件存入忽略的下载缓存，准备结果进入 `assets/prepared/` 并由应用打包。

准备与验证完成了以下具体事项：

1. 避免多个卫星 kernel 自带的太阳、地球和系统质心 segment 因加载顺序无意覆盖选定基础星历。
2. 保留本体与系统质心之间所需的连接；只截取可见目标而删除必需中心会导致查询失败。
3. 阅读卫星模型注释对基础星历的约定，固定最终版本和优先级，再生成独立参考样本；不靠文件名猜测模型一致性。
4. 在 UTC 输入区间两端保留时间转换和 segment 的正常边界余量。逐个目标验证整段连续覆盖，不能仅看文件总起止时间。
5. 裁剪后的 kernel 按 NAIF 规则更新派生文件名和制作方信息，并保留原始模型／数据贡献者说明。

实测七份 SPK 共约 547.7 MiB：DE442s 20.80、MAR099 225.24、JUP365 86.52、SAT441 133.71、URA111L 46.37、NEP097 16.44、PLU060 18.65 MiB。加上文本内核、地图和说明，准备资源约 610.81 MiB；文件字节总量与文件系统分配空间可能不同。完整应用运行时不依赖在线查询或下载；准备脚本复用未变化的输入和现有结果，不让普通 build 重新下载全部资源。

### 3.3 计算与精度约定

- 使用几何状态，统一 `ECLIPJ2000`、ET、km 与 km/s；输入／显示的 UTC 由同一套 LSK 转换。
- 未来 UTC 按随包闰秒规则换算；资源版本记录说明采用的时间表。应用不自行预测未来新增闰秒。
- 姿态采用适用的 IAU／PCK 模型，明确它与真实天气或精密地球定向观测的区别。
- 参考轨道使用 CSPICE 的状态／轨道要素转换，避免在 Scoop 再实现一套主要天体轨道算法。
- SPICE 出错采用返回式处理，由薄 C 适配提取信息、清理错误状态，再转成应用错误；不能让默认原生错误策略终止整个 UI。
- CSPICE 的 kernel 和错误状态由一个应用级 owner 管理，同一时刻求值串行进行。首期没有并行 SPICE 查询的实际必要。
- 应用中的固定 N0067 f2c 文件层只读打开已有内核；生成子集的独立准备工具仍可正常写入输出。模式适配集中在 `ephemeris.c`，不修改已下载的官方 Toolkit。

位置精度通过固定日期的独立参考样本核对。可用 [JPL Horizons](https://ssd.jpl.nasa.gov/horizons/) 导出相同目标、中心、时标、坐标框架及几何修正下的向量。需记录 Horizons 与随包模型的版本差异，再确定有依据的误差容限；不把不同定义下的差异误判为程序 bug，也不凭肉眼相似宣称高精度。

## 4. 纹理、形状与说明资料

### 4.1 来源优先级

优先选择 NASA／JPL／USGS／ESA 任务数据制作的球面地图，以及明确标注许可与处理方式的可再分发纹理。每项记录：文件、作者／机构、原始链接、许可／使用条件、颜色处理、像素分辨率、球面投影、经纬方向、观测覆盖和项目进行的处理。

首版使用 [CelestiaContent](https://github.com/CelestiaProject/CelestiaContent) 的观测资料地图，固定提交 `1bbbf41ed4639a17fd9a884fd843e425caedd9a3`。全部 31 个天体有各自地图，另有地球云层、地球夜景、地球与月球法线图，以及两张星环径向图，共 37 张，文件总量约 62.74 MiB。

清单记录原始文件路径、随包文件名、渲染身份和单独许可文件入口。地图按原图准备，不进行生成式补全；随包 README 记录具体作者与观测资料。月球图使用上游 LRO／CGI Moon Kit 的处理结果，地球使用上游列明的地表、BMNG 与 Natural Earth 数据，其他地图按单独说明处理。

颜色贴图在线性空间受光。单通道灰度 JPG 扩展为 RGB，避免误着色；地球 LA 云图的透明度在 macOS 位于 GPU RG 纹理的 G 通道，在 Linux 由 GdkPixbuf 展开为 RGBA 后位于 alpha，分别处理。两个平台的真实 GPU 测试均覆盖全部地图、灰度一致性、地球昼夜和同一帧的确定性。

### 4.2 资源规格

| 类型 | 设计规格 |
| --- | --- |
| 常规颜色图 | 优先 2:1 经纬展开、sRGB，首批通常 2K 级；近景按需要加载 4K |
| 法线／高程／粗糙度 | 线性数据，注明真实地图或可解释的派生方式 |
| 地球云层 | 单独透明层；标为代表性云图，不承诺指定日期的天气 |
| 金星、Titan | 从外部可见的云雾层，地表／雷达资料放在有说明的详情中 |
| 木星、土星 | 云带与典型特征地图；大红斑等随自转移动，但不承诺历史云流重建 |
| 土星环、天王星环 | 径向颜色／光学透明度，明确内外半径、环平面方向 |
| 小型不规则天体 | 实测比例的三轴椭球或授权低面数形状，配套正确方向的纹理 |
| 远景标记 | 简单几何与天体代表色；不代替近景外观 |

保留上游原图分辨率，运行时准备 mipmap；球面采用北方在上、零经线在图中部的经纬展开映射，与 IAU 本体坐标旋转组合。天空背景保持克制，太阳辉光不遮住内行星。整体资源量通过分辨率与按需加载控制；不以省资源为由把主要卫星全部画成同一张灰色纹理。

未知的远侧地表不通过 AI 随意生成再当作观测数据。需要重建或艺术补全的资源必须标注处理方式，详情保留来源与已知限制。

### 4.3 文字数据

首版静态资料包括中英文名、类别、所属系统、真实平均半径、公转周期、自转定义、主要表面特征及简介。火卫一／二的三轴比例和巨行星扁率用于展示形状及物理表面映射；姿态由 PCK 求得。阴影使用真实位置和物理半径，非球形遮挡物以物理包围球近似。量值保留单位和来源，不从显示尺寸反推。

动态资料包括当前 UTC、距太阳的真实距离、日心速度和当前选择状态。半径、周期与说明在目录中统一定义，浮卡和详情共用这些数据。

## 5. 许可、署名与网络

[NAIF 使用规则](https://naif.jpl.nasa.gov/naif/rules.html)允许将 SPICE 模块作为基于 SPICE 的应用组成部分提供，也说明了完整 Toolkit 镜像及派生 kernel 的不同要求。项目应只随应用提供所需模块与文档，保留说明；不建立完整 Toolkit 下载镜像。

[NASA 媒体使用说明](https://www.nasa.gov/nasa-brand-center/images-and-media/)通常允许其内容用于教育和信息展示，但页面内第三方作品可能有不同权利；每个素材仍按自己的署名和条款处理。NASA 标志不作为本应用品牌。

应用打包包含 `THIRD-PARTY-NOTICES` 和逐项素材来源；原始数据、程序依赖和纹理的许可分别记录。CSPICE 的原始免责声明与版本说明，以及地图 README、单独 `.license` 和其引用的原许可文本均已随包保存。

网络只用于显式资源准备。脚本读取调用进程的 `https_proxy` 等标准环境变量，脚本固定使用仓库内的下载缓存；不修改用户系统代理，也不把私人代理地址硬编码进仓库。
